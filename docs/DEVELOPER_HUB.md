# DEVELOPER_HUB.md — the in-app developer guide (contract)

The Developer Hub is the interactive, self-updating starter guide for people building test apps on the
framework. It lives in **Help → Developer** and is **developer-only**: it is never packaged into a client
station. (Customers get the User portal/manual — see `docs/contracts/PORTAL.md` once that module lands.)

## Principle: sort content by how fast it goes stale

| Kind | Source | Freshness mechanism |
|---|---|---|
| **Facts** (version, releases, modules, permissions, roles, step types, capabilities, controller ops, routes, skills) | generated by `tools/gen_devguide.py` → `docs/generated/facts.{json,md}` | **drift gate**: `backend/tests/test_devguide_facts.py` + a CI step fail when stale; the facts embed the framework version, so a release can't be cut without regenerating |
| **Narrative** (principles, ownership, first app, gotchas, glossary, contracts map) | hand-authored `docs/help/dev/guide/*.md` | kept short; where prose would restate a fact it embeds a live widget instead; every real bug adds a Gotchas entry |
| **Diagrams** | inline-SVG React components (`widgets/Diagrams.tsx`) | structural only — no counts that can rot; theme-aware |
| **Screenshots** | `tools/screenshots` → `docs/assets/screens/*.png` + `manifest.json` | each image is stamped with the framework version and a hash of the screen's source file; the UI shows "captured at vX" and warns when the screen has changed since (soft gate) |

## Layout

```
docs/help/dev/guide/*.md      hub pages (registered in modules/help/catalog.py, sections Start here / Concepts / Reference / Stay current)
docs/generated/               facts.json + facts.md   (generated — never edit)
docs/assets/                  SHARED image library (also used by the user manual): manifest.json + screens/*.png
frontend/src/components/help/ Markdown.tsx (conventions below), HelpImage.tsx, widgets/*
tools/gen_devguide.py         the generator            tools/screenshots/   the capture pipeline (dev-only)
```

## Markdown conventions (Markdown.tsx)

- `![alt](asset:<id>)` — a library image by manifest id (fetched with the auth header, shown with a capture badge)
- `[text](help:<page-id>#anchor)` — in-app link; deep links are `/help?page=<id>#anchor`
- ```` ```tmf:<widget> ```` — a live widget; the block body is its argument. Registered in
  `widgets/register.ts`: `facts` (version|modules|capabilities|ops|routes|skills), `permissions-matrix`,
  `step-types`, `changelog`, `live-app`, `ownership`, `skill-picker`, `checklist`, `diagram`
  (architecture|boundary|chain|release). An unknown widget renders a visible error box.

## Drift gates (all run in CI)

- generated facts current; every catalog page resolves to a file **and** every `docs/help/**.md` is in the catalog
- no duplicate page ids; every `help:` link targets a real page; every `asset:` id exists in the manifest;
  every `tmf:` block names a registered widget

## Never shipped to a client station

1. `build_release.copy_user_docs` is an **allowlist** (`docs/help/user/**` + the images the user-audience
   manifest references). Developer docs, `docs/generated`, dev-only images are not copied.
2. `help.catalog.is_frozen()` hides every `dev` page, dev-only asset and `/help/facts` in a built station.
3. Tests cover both (`test_build_release.py`, `modules/help/tester/test_help.py`).

## Working on it

| To… | Do |
|---|---|
| add/change a hub page | edit `docs/help/dev/guide/*.md`; add a `Page(...)` row for a new file |
| add a widget | component in `widgets/`, one `registerWidget("name", C)` line in `register.ts`, a test |
| refresh facts | `python tools/gen_devguide.py` (CI: `--check`) |
| refresh screenshots | `cd tools/screenshots && npm install && npm run capture` — needs Microsoft Edge and a free `:8000`; it runs a **pristine throw-away station** (fresh state, example config, demo data, the reference LabVIEW stub if a broker is up) so the shared images never show a fork's branding or data |
| record a lesson | append to `docs/help/dev/guide/gotchas.md` |
